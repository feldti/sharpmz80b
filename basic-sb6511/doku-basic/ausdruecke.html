Ausdrücke und Variablen

Rangfolge und Auswertungsroutinen

Die Ausdrucksauswertung ist ein rekursiver Abstieg. Jede Stufe ruft die nächsthöhere für ihre Operanden auf:

Stufe Routine Adresse Operatoren
1 (niedrigste) EVAL_EXPR 254Bh Vergleiche = <> >< < > <= =< >= =>
2 EVAL 25EBh + - (bei Strings + = Verkettung)
3 TERM 264Bh * /
4 POWER 2664h ^
5 (höchste) PRIMARY 26BAh Vorzeichen, Zahl, Variable, FN, ( … ), String, Funktion, π

Es gibt keine logischen Operatoren (AND, OR, NOT fehlen in den Tabellen). Bedingungen lassen sich nur mit Vergleichen und Arithmetik verknüpfen, etwa (A>1)*(B<5) für „und“.

Ein Vergleich liefert −1 für wahr und 0 für falsch (CMP_TRUE/CMP_FALSE). IF prüft nur, ob das Ergebnis ungleich 0 ist.

Bemerkenswert: EVAL – die Stufe ohne Vergleiche – ist der Einsprung für fast alle Befehle, die eine Zahl erwarten. Nur wo ausdrücklich ein Vergleich erlaubt sein soll – LET, IF, PRINT, Klammern in PRIMARY, IMAGE/P, WRT, CMD und RSO – wird EVAL_EXPR benutzt. PRINT A=1 gibt also −1 oder 0 aus, während z. B. POKE oder ON keinen Vergleich ohne Klammern annehmen.

Ergebnis einer Auswertung

Register Bedeutung
D = 0 Zahl; der Wert steht als 5-Byte-Gleitkommazahl bei (VALSP)
D ≠ 0 String; E = Nummer des Eintrags in den String-Zwischenwerten (GETSTR liefert Adresse und Länge)
A das nächste Zeichen hinter dem Ausdruck
HL Textzeiger hinter dem Ausdruck

Der Wertestack

Zwischenergebnisse liegen auf einem eigenen Stapel am Ende der dynamischen Bereiche (VALSP, 7094h), 5 Bytes je Eintrag. APPLY_OP legt den linken Operanden ab, erhöht VALSP um 5, wertet den rechten Operanden über die übergebene Routine aus und ruft dann den Operator über FUNC_TAB auf. Gemischte Typen (Zahl und String) ergeben Fehler 4.

DISPATCH setzt den Wertestack vor jeder Anweisung zurück. Ein Ausdruck verbraucht deshalb nie dauerhaft Speicher.

Typprüfung

Routine prüft
REQ_STR String verlangt; Zahl: Fehler 4
CHKSTRTYPE Zahl verlangt; String: Fehler 4
EVAL_INT Zahl 0–65535 (Nachkommastellen abgeschnitten), sonst Fehler 3
EVAL_BYTE Zahl 0–255, sonst Fehler 3
EVAL_ADDR $ mit bis zu 4 Hexziffern oder ein Ausdruck (wie EVAL_INT)

FUNC_TAB – Operatoren und Funktionen

FUNC_TAB (2949h) hat 49 Einträge:

Index Inhalt
0–8 Vergleiche, Token 83h–8Bh (89h steht für =)
9–11 unbenutzt (ERR_01)
12–16 + - * / ^ (kein Token, Index wird im Code gesetzt)
17–36 Funktionen A0h–B3h: LEFT$( RIGHT$( MID$( LEN( CHR$( STR$( ASC( VAL( PEEK( TAB( SPACE$( SIZE ERL ERN EOF( STRING$( POINT( CHARACTER$( CSR POS
37–48 mathematische Funktionen C0h–CBh: RND( SIN( COS( TAN( ATN( EXP( INT( LOG( LN( ABS( SGN( SQR(

PRIMARY unterscheidet die beiden Funktionsgruppen: Bei A0h–B3h liest die Funktion ihre Argumente selbst (sie hat oft mehrere oder Strings). Bei C0h–CBh wird das eine Argument vorher ausgewertet; die Routine bekommt in DE einen Zeiger auf den Wert und schreibt das Ergebnis dorthin.

Funktionen im Überblick

Funktion Ergebnis / Besonderheit
LEFT$(s,n), RIGHT$(s,n) Anfang bzw. Ende des Strings (STR_CUT schneidet auf dem Wertestack zu)
MID$(s,p,n) Teilstring ab p; statt n darf - stehen: Rest ab p. p = 0: Fehler 3
LEN(s), ASC(s) Länge, Code des ersten Zeichens (ASC(""): Fehler 3)
CHR$(n), STR$(x), VAL(s) VAL eines leeren oder nicht numerischen Strings ergibt 0
PEEK(adr) Byte aus dem Speicher; Adresse auch $hex
SPACE$(n), STRING$(s$,n) n Leerzeichen bzw. n-mal das erste Zeichen von s$ (STR_FILL; leerer String: Fehler 3)
TAB(n) nur in PRINT; als Funktion Fehler 1
SIZE freier Speicher in Bytes
ERL, ERN Zeile und Nummer des letzten Fehlers
POINT(x,y) Pixelzustand 0–3 (x 0–319, y 0–199)
CHARACTER$(x,y) Zeichen an einer Textbildschirmposition
CSRV, CSRH / POSV, POSH Cursorzeile bzw. -spalte des Textbildschirms / Grafikposition y bzw. x (Token CSR bzw. POS, gefolgt von V oder H)
RND(x) x > 0: nächste Zufallszahl; x ≤ 0: Startwert zurücksetzen
SIN COS TAN ATN EXP LN LOG SQR INT ABS SGN siehe Gleitkomma

Variablen

Namen

GETNAME liest einen Buchstaben und optional einen zweiten Buchstaben oder eine Ziffer. Weitere Buchstaben und Ziffern werden überlesen – nur zwei Zeichen zählen (COUNT und CO sind dieselbe Variable). Ein angehängtes $ macht den Namen zu einer Stringvariablen, ( zu einem Feld. Der Name wird als zwei Bytes gespeichert (zweites Byte 20h bei einbuchstabigen Namen).

Zahl- und Stringvariablen, Zahl- und Stringfelder liegen in getrennten Listen: A, A$, A(1) und A$(1) sind vier verschiedene Objekte.

Speicherformat

Art Liste Eintrag
Zahlvariable P_NUMVAR Name (2) + Wert (5)
Stringvariable P_STRVAR Name (2) + Länge (1) + Text + 0Dh
Feld P_ARRAYS … Name (2) + Dimensionen (2) + (n+1)·(m+1) Elemente
Zahl-Element 5 Bytes
String-Element Länge (1) + Text + 0Dh, anfangs 2 Bytes (0, 0Dh)
DEF FN P_DEFFN Funktionsbuchstabe, Parameterbuchstabe, Tokentext, 0Dh

Jede Liste endet mit dem Wort 0000h. Gesucht wird linear (NUMVAR, STRVAR, LISTKEY_CMP).

Anlegen und Suchen

  • NUMVAR sucht eine Zahlvariable; fehlt sie, wird sie am Listenende mit dem Wert 0 angelegt. Zurück kommt DE = Adresse des Werts.
  • STRVAR sucht eine Stringvariable bzw. legt sie leer an (LK2_NEW). Der Name TI wird vorher abgefangen: TI$ ist keine echte Variable, sondern liest die Uhr (TI_READ, Format "hhmmss", 24 Stunden).
  • Neue Einträge entstehen mit MEMINS_ADJ: alles dahinter rückt auf, ADJ_PTRS korrigiert die Bereichszeiger.

Zuweisung (LET)

ST_LET (1F99h) wertet zuerst den Ausdruck hinter = aus und bestimmt erst danach die Variable. Beide Angaben werden mit SAVEPAR0/SAVEPAR1 nach 6B00h/6B04h gelegt; ASSIGN (1FD4h) führt die Zuweisung aus:

  • Typen verschieden: Fehler 4.
  • Zahl: 5 Bytes kopieren.
  • String: der Platz der Variablen wird an die neue Länge angepasst (ASG_RESIZE, ASG_SHRINK, über MEMINS/MEMDEL mit Zeigerkorrektur), dann der Text kopiert.
  • TI$: der Wert muss sechs Ziffern hhmmss sein (sonst Fehler 3); damit wird die Uhr gestellt (ASG_TI).

Es gibt keine Speicherbereinigung (Garbage Collection): Strings liegen immer genau so groß wie nötig an ihrem Platz, und Zwischenergebnisse verfallen mit dem Ende jeder Anweisung. Dafür kostet jede Längenänderung ein Verschieben aller dahinter liegenden Daten.

INPUT, READ, GET, INP@ und die GP-IB/RS-232C-Leseanweisungen benutzen denselben Weg (GETVAR → SAVEPAR1, Wert → SAVEPAR0, ASSIGN).

Felder (DIM)

DIM name\[$\](n[,m])[,…] legt ein Feld mit höchstens zwei Dimensionen an, jeder Index 0–255. Die Elemente werden mit 0 bzw. leeren Strings vorbelegt. Ein bereits vorhandenes Feld wird übergangen; passen die neuen Grenzen nicht hinein, folgt Fehler 3.

Anders als in vielen BASIC-Dialekten werden Felder nicht automatisch angelegt: Der Zugriff auf ein Feld ohne DIM ergibt Fehler 3 (ARR_ELEM), ebenso ein zu großer Index.

ARR_FIND wählt die Liste nach Typ und Dimensionszahl. Beim Zugriff auf ein Stringelement werden die Einträge über ihre Längenbytes abgezählt (ARR_STRPOS) – lange Stringfelder sind deshalb langsam.

CLR und das Löschen von Variablen

Befehl Wirkung auf Variablen
CLR Variablen, Felder, DEF FN, Strings löschen; Programm bleibt
RUN wie CLR, dazu Dateien schließen und Stacks zurücksetzen
RUN zeile, GOTO Variablen bleiben
NEW Programm und Variablen löschen
CHAIN Variablen bleiben über den Programmwechsel
Programmzeile editieren Variablen bleiben, CONT ist gesperrt
Fehler (ohne ON ERROR) Dateien und Stacks werden zurückgesetzt, Variablen bleiben

Strings

  • Höchstlänge 255 Zeichen; eine längere Verkettung ergibt Fehler 5.
  • Zeichen ≥ 80h sind erlaubt (Grafikzeichen, Bit 7 = inverse Darstellung), außerhalb von Strings im Programmtext aber nicht.
  • Der Vergleich (STRCMP) prüft zuerst die Länge: Strings verschiedener Länge werden nur nach ihrer Länge geordnet, ohne den Inhalt anzusehen. Erst bei gleicher Länge wird Zeichen für Zeichen nach dem Code verglichen. Ein Sortieren mit </> ergibt deshalb keine alphabetische Reihenfolge, wenn die Strings verschieden lang sind; = und <> arbeiten wie erwartet.
  • STRLIT liest String-Konstanten (in Anführungszeichen bis ", sonst bis , bzw. Zeilenende – so liest auch INPUT Strings ohne Anführungszeichen). STR_NEW legt jedes Zwischenergebnis als neuen Eintrag in P_STRTMP an.
