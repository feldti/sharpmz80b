Interpreterschleife und Programmablauf

Überblick

Die Ausführung kreist um wenige Routinen bei 1CFDh–1D9Ch:

             ┌──────────────────────────────────────────────────────┐
             ▼                                                      │
 NEXTSTMT  (HL = TXTPTR)                                            │
     │  ":"  ──────────────► EXECSTMT                               │
     │  0Dh  ─► NEXTLINE: Link 0? ─► END_PRG / BAS_READY            │
     │              │                                               │
     │          NL_SRQ (ON SRQ?) ─► NL_NEXT: CURLINE := Link+Nr.    │
     │              ▼                                               │
     │          EXECSTMT: TXTPTR := HL                              │
     │              ▼                                               │
     │          EXECSTMT2: ERRCTX_SAVE (ON ERROR), BREAK prüfen     │
     │              ▼                                               │
     │          DISPATCH: Wertestack leeren, Token lesen            │
     │              │  < 80h  ─► ST_LET                             │
     │              │  80h,n  ─► STMT_TAB[n]  (JPTAB)               │
     │              ▼                                               │
     │          ST_xxx: Parameter lesen, ausführen ─► JP NEXTSTMT ──┘

NEXTSTMT (1CFDh) und NEXTSTMT_HL

NEXTSTMT holt den Textzeiger aus TXTPTR, NEXTSTMT_HL nimmt ihn aus HL. Nach Leerzeichen muss entweder : folgen (dann geht es in derselben Zeile weiter) oder 0Dh (Zeilenende). Alles andere ergibt Fehler 1 – so wird überzähliger Text hinter einer Anweisung erkannt.

NEXTLINE und NL_SRQ

Am Zeilenende liest NEXTLINE den Link der aktuellen Zeile aus CURLINE. Im Direktmodus (CURLINE = 0) geht es zurück nach BAS_READY. Sonst:

  • ON SRQ: Ist SRQ_ON gesetzt und die SRQ-Leitung der GP-IB-Karte aktiv (Port C0h, Bit 2), wird SRQ_ON gelöscht und die Ausführung bei der Zeile in SRQ_LINE fortgesetzt – ein einmaliger, zeilengenauer „Interrupt“.
  • Link 0 bedeutet Programmende → END_PRG.
  • Sonst werden Link und Zeilennummer der neuen Zeile nach CURLINE/CURLNUM kopiert.

EXECSTMT2 – vor jeder Anweisung

  1. Ist ON ERROR aktiv (ONERR_FLAG = 1), sichert ERRCTX_SAVE die aktuelle Zeile und den Textzeiger nach ERRCTX_*. Daraus liefert ERL die Fehlerzeile, und RESUME setzt dort wieder auf.
  2. BREAK-Abfrage (BRKCHK und eine zweite Tastaturzeile über die PIO). Wird abgebrochen, merkt sich CONT_POS die Stelle mit Kennung 2 („Anweisung wiederholen“), dann BREAK.

DISPATCH (1D5Eh) und JPTAB

DISPATCH setzt den Wertestack zurück (VALSP := Anfang von P_STRTMP; damit verfallen auch alle String-Zwischenwerte der vorigen Anweisung) und liest das Zeichen am Textzeiger:

  • Byte < 80h: keine Anweisung – implizites LET (ST_LET).
  • 80h, 80h+n: Index n in STMT_TAB (100 Einträge × 2 Bytes ab 1D9Dh). Jedes andere erste Byte (81h, 82h, Funktionstoken) ergibt Fehler 1.

JPTAB holt die Adresse aus der Tabelle, legt sie mit EX (SP),HL auf den Stack und springt mit RET hinein. HL zeigt dabei auf das erste Zeichen hinter dem Token. Dieselbe Routine verteilt auch über FUNC_TAB.

Freie Plätze in STMT_TAB zeigen auf ERR_01. Auch THEN (Anweisung Nr. 12) und die Funktion EOF( (in FUNC_TAB) sind mit ERR_01 belegt: sie werden nur innerhalb von IF ausgewertet.

Wie eine Anweisungsroutine aussieht

Eine Routine ST_xxx bekommt HL = Textzeiger, liest ihre Parameter mit den Hilfsroutinen und endet mit JP NEXTSTMT (nach CHK_EOS, das TXTPTR setzt) oder JP NEXTSTMT_HL. Sie kehrt nicht mit RET zurück. Ein typisches Beispiel ist POKE:

ST_POKE:                        ; POKE adresse, wert
        CALL    EVAL_ADDR       ; DE = Adresse ($hex oder Ausdruck)
        CALL    SKIPCOMMA       ; Komma überlesen
        PUSH    DE              ; Adresse merken
        CALL    EVAL_ADDR       ; DE = Wert
        LD      A,D
        OR      A
        JP      NZ,ERR_03       ; Wert > 255: Fehler 3
        EX      (SP),HL         ; HL = Adresse, Textzeiger auf den Stack
        LD      (HL),E          ; Byte schreiben
        POP     HL              ; Textzeiger zurück
        JP      NEXTSTMT_HL     ; ":" oder Zeilenende muss folgen

Die Seite Einen Befehl einbauen erklärt das ausführlich.

Programmiertechniken im Code

Drei Muster tauchen überall auf und erklären viele scheinbar „falsche“ Stellen im Listing.

Inline-Parameter

Viele Hilfsroutinen lesen Daten, die im Code direkt hinter dem CALL stehen, und kehren hinter diese Daten zurück:

Aufruf Bedeutung
CALL SYNCHK / DEFB z Zeichen z muss folgen, sonst Fehler 1
CALL CHK_CHR_ALT / DEFB z / DEFW ziel folgt z, weiter dahinter; sonst Sprung nach ziel
CALL MUL16 / DEFW fehler 16-Bit-Multiplikation, bei Überlauf Sprung nach fehler
CALL FINDLINE / DEFW ende Zeile suchen, Programmende → ende
CALL DIR_SCAN / DEFW handler handler für jeden Verzeichniseintrag aufrufen
CALL FTAB_SCAN / DEFW handler handler für jeden Eintrag der Dateitabelle

Die Helfer JP_INLINE (zur Inline-Adresse springen) und RET_SKIP2 (dahinter zurückkehren) setzen das um. Im Listing heißen solche Daten Dxxxx.

Die Kette der Fehlereinsprünge

ERR_01: LD      A,01h
        DEFB    01h             ; = LD BC,nn: verschluckt das nächste LD A,n
ERR_02: LD      A,02h
        DEFB    01h
ERR_03: ...

Ein Sprung nach ERR_nn lädt die Nummer; das Byte 01h bildet mit dem folgenden LD A,n einen LD BC,nn-Befehl, der nichts bewirkt. So „rutscht“ jeder Einsprung ohne weiteren Sprung bis zum Ende der Kette und weiter nach ERROR. 70 Einsprünge kosten so nur 3 Bytes pro Fehler.

Selbstmodifizierender Code

Viele Routinen ändern Operanden anderer Befehle zur Laufzeit (LD (Lxxxx+1),A), etwa:

  • INP@/OUT@ schreiben die Portnummer in einen IN/OUT-Befehl.
  • LIST_DEV wird für LIST/P auf 1 gesetzt.
  • FINDLINE2 sucht mit der zuletzt in FL_TARGET eingesetzten Zeilennummer weiter.
  • END_SWAP merkt sich, dass ein per SWAP geladenes Programm läuft.
  • Die Grafik setzt Bitbefehle (SET/RES/BIT n,(HL)) und INC/DEC für Bresenham ein.
  • Die RS-232C-Erweiterung trägt Portnummern ein, damit derselbe Code für beide Kanäle dient.

Stacks des Interpreters

Neben dem Z80-Stack verwaltet das BASIC drei eigene Stapel in festen Bereichen. Sie wachsen abwärts; INITVARPTR setzt sie zurück.

Stapel Zeiger Eintrag Tiefe Fehler
GOSUB GOSUB_SP (Start 7240h) 7 Bytes: CURLINE (Link, Nr.), TXTPTR, FOR_CNT 15 10
FOR FOR_SP (Start 71D7h) 19 Bytes: Kopie von FOR_VAR … TXTPTR 15 11
FN FNPAR_SP (Start 70BAh) 6 Bytes: gesicherte Parametervariable 5 12

FOR … NEXT

FOR var = a TO b [STEP c] (ST_FOR, 216Fh):

  1. Laufvariable suchen bzw. anlegen (GETNAME_SN, NUMVAR), Startwert zuweisen.
  2. Nach dem Token TO (9Eh) den Endwert, nach STEP (9Fh) die Schrittweite auswerten; ohne STEP gilt 1.
  3. Der Eintrag wird in FOR_VAR … FOR_LIMIT zusammengesetzt: Adresse der Variablen (2), Schrittweite (5), Vorzeichen der Schrittweite (1), Endwert (5), danach CURLINE (4) und TXTPTR (2) – zusammen 19 Bytes.
  4. Gibt es schon einen Eintrag für dieselbe Variable, wird er samt allen jüngeren entfernt (so verhält sich ein erneut betretenes FOR korrekt).
  5. Eintrag auf den FOR-Stack, FOR_CNT und FOR_DEPTH erhöhen.

Die Schleife wird immer mindestens einmal durchlaufen; geprüft wird erst bei NEXT.

NEXT [var[,var…]] (ST_NEXT, 2204h) sucht den passenden Eintrag (ohne Variable den jüngsten; jüngere werden verworfen, keiner gefunden: Fehler 13), addiert die Schrittweite (OP_ADD) und vergleicht je nach Vorzeichen mit dem Endwert (FP_CMP). Läuft die Schleife weiter, werden CURLINE und TXTPTR aus dem Eintrag geholt; ist sie fertig, wird der Eintrag entfernt und mit der nächsten Variablen hinter , weitergemacht.

GOSUB … RETURN

GOSUB zeile legt CURLINE, TXTPTR und FOR_CNT (7 Bytes) auf den GOSUB-Stack und setzt FOR_CNT = 0: jede GOSUB-Ebene zählt ihre FOR-Schleifen selbst. RETURN verwirft die FOR-Einträge der aktuellen Ebene und holt die drei Werte zurück (ohne GOSUB: Fehler 14). Ein RETURN mitten aus einer FOR-Schleife ist damit sauber.

DEF FN und FN

DEF FNx(y) = ausdruck kopiert den Tokentext hinter = in die Liste P_DEFFN (Eintrag: x, y, Text, 0Dh); eine vorhandene Definition wird ersetzt. Funktions- und Parametername sind je ein Buchstabe.

FNx(arg) (FN_CALL) sucht die Definition (fehlt: Fehler 15), sichert den aktuellen Wert der Variablen y auf dem FN-Stack, weist ihr das Argument zu, wertet den gespeicherten Text mit EVAL aus und stellt y wieder her. Die Rekursionstiefe ist auf 5 begrenzt (Fehler 12).

Kontrollanweisungen

Anweisung Routine Verhalten
GOTO z ST_GOTO Zeile suchen (GOTO_HL, fehlt: Fehler 16), dort weiter. Auch Ziel von THEN z, ON … GOTO, RESUME z
GOSUB z / RETURN ST_GOSUB / ST_RETURN siehe oben
IF b THEN z / THEN anw / GOTO z / GOSUB z ST_IF Bedingung = 0: Rest der Zeile überspringen (IF_FALSE); auch Anweisungen hinter : gehören zum THEN-Zweig
IF EOF(#n) … ST_IF Sonderform: prüft das EOF-Byte im Dateitabellen-Eintrag (Datei nicht offen: Fehler 44)
ON a GOTO/GOSUB z1,z2,… ST_ON a = 0 oder > 255: weiter mit der nächsten Anweisung; gibt es weniger Ziele als a, ebenfalls
ON ERROR GOTO z ST_ONERR Fehlerbehandler setzen, siehe Fehler
ON SRQ GOTO z ST_ON → ST_SRQ GP-IB-Service-Request, geprüft in NL_SRQ
END ST_END Programm beenden, CONT möglich; nach SWAP zurück ins rufende Programm
STOP ST_STOP wie END, zusätzlich Meldung *STOP IN z
CONT ST_CONT nur im Direktmodus; ohne gesicherte Stelle Fehler 17
RUN [z] ST_RUN ohne Argument: Variablen löschen, von vorn. Mit Zeile: dort starten, Variablen bleiben. Mit "datei": laden und starten
NEW ST_NEW CONT sperren, Programm und Variablen löschen

Die meisten Ablaufbefehle (GOSUB, RETURN, IF, ON, INPUT, END, STOP, ON ERROR …) sind nur im Programm erlaubt (CHK_NODIRECT), Editierbefehle wie LIST, AUTO, CONT, SAVE, DIR, KLIST nur im Direktmodus (CHK_DIRECT). Sonst: Fehler 19.

CONT

CONT_POS sichert CURLINE und TXTPTR und eine Kennung in CONT_FLAG:

CONT_FLAG gesetzt durch CONT macht
0 CONT_CLR (Editieren, NEW, Laden) Fehler 17
1 END, STOP weiter mit der nächsten Anweisung
2 BREAK während des Programms die unterbrochene Anweisung wiederholen
negativ (80h) BREAK während INPUT INPUT neu beginnen

READ, DATA, RESTORE

READ läuft über denselben Zuweisungscode wie INPUT, mit dem Pseudogerät FILE_NO = 81h. READ_NEXT holt das nächste Element aus DATA_PTR; ist die aktuelle DATA-Anweisung erschöpft, sucht DATA_SEARCH die nächste DATA-Anweisung im Programm (keine mehr: Fehler 24). DATA-Text wird beim Tokenisieren nicht verändert. RESTORE [z] setzt DATA_FLAG zurück bzw. beginnt die Suche ab Zeile z.

Programme verketten: CHAIN und SWAP

Befehl Wirkung
RUN "datei" Programm laden und von vorn starten, Variablen gelöscht
CHAIN datei Programm laden und starten, Variablen bleiben (CHAIN_MODE = 1)
SWAP datei laufendes Programm samt Variablen (ab 7096h) als Auslagerungsdatei (Typ 80h/81h) auf die Diskette schreiben, das andere Programm laden und starten. Dessen END kehrt über SWAP_BACK ins rufende Programm zurück; SWAP im SWAP: Fehler 25
APPEND datei Zeilen eines Programms hinzuladen; gleiche Nummern ersetzen vorhandene Zeilen
