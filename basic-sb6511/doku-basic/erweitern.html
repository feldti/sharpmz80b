Einen Befehl einbauen

Übernommen aus docs/NEUER_BEFEHL.md.

Stand: 26.10.2026

Überblick

Ein neuer Befehl braucht drei Änderungen in SB6511_RS232.asm: das Schlüsselwort auf einem freien Platz in KWTAB_STMT, die Adresse der Routine im passenden Eintrag von STMT_TAB und die Routine selbst, an beliebiger Stelle im BASIC-Teil. Die Quelle ist ab BAS_COLD (1222h) verschiebbar: Wird die Tabelle länger oder kommt Code dazu, passt der Assembler alle Adressen an. Tokenizer, LIST und Ausführung sind tabellengesteuert; am Interpreter ändert sich nichts.

Als Beispiel dient DRAW x1,y1,x2,y2: eine Linie von (x1,y1) nach (x2,y2). Der Leitfaden behandelt Schlüsselwort, Verteilung, Parameterabfrage, Bereichsprüfung und Übergabe. Gezeichnet wird mit der vorhandenen Linienroutine von LINE (LINE_SET); GR_DRAWLINE ist nur die Brücke dorthin.

Alle Namen beziehen sich auf den Stand des Disassemblys im Repo mf/basic-sb6511. Das Beispiel ist genau so eingebaut und im Emulator geprüft worden (Ergebnisse in Schritt 3).

Wie ein Befehl verarbeitet wird

Ein Befehl durchläuft vier Stationen; nur die erste und die dritte kennen ihn über eine Tabelle, die vierte ist der neue Code.

  1. Eingabe (CRUNCH): sucht an jeder Stelle der Zeile in KWTAB_STMT. Eintrag Nr. n wird zum Token 80h, 80h+n. Leerzeichen innerhalb des Worts werden überlesen.
  2. Auflisten (LISTLINE): wandelt 80h, 80h+n über dieselbe Tabelle zurück in Klartext. Nichts zu tun.
  3. Ausführen (DISPATCH): liest das Token, holt STMT_TAB[n] und springt die Routine an. Ein Byte unter 80h führt zu LET.
  4. Routine (ST_…): liest ihre Parameter, führt aus und springt nach NEXTSTMT bzw. NEXTSTMT_HL.

Zustand beim Einsprung in die Routine:

Was Wert
HL zeigt auf das erste Zeichen hinter dem Token
TXTPTR noch nicht aktualisiert
Stack Rückkehr ist nicht vorgesehen: die Routine endet mit JP
A, BC, DE ohne Bedeutung

Zwei Wege zurück in die Interpreterschleife:

  • JP NEXTSTMT liest den Textzeiger aus TXTPTR. Passt zu CHK_EOS, das TXTPTR auf das Anweisungsende setzt.
  • JP NEXTSTMT_HL nimmt HL als Textzeiger. Passt, wenn HL nach der Parameterabfrage noch auf das Anweisungsende zeigt.

Beide prüfen, ob dort : oder das Zeilenende steht; sonst Fehler 1.

Regeln

Adressen passt der Assembler an, Tokennummern nicht: Die Nummer eines Befehls ist seine Position in KWTAB_STMT. Sie steht in gespeicherten Programmen und an einigen Stellen fest im Code (CP 0AEh für EOF(, die Inline-Bytes 9Eh/9Fh für TO/STEP usw.). Ein neues Wort ersetzt deshalb einen freien Platz (FFh) und wird nicht dazwischen eingefügt.

Regel Warum
Freien Platz Nr. 56, 60, 61, 74, 90 oder 99 nehmen Nr. 3 ist frei, aber CRUNCH behandelt Nr. 0–3 wie REM: der Rest bis : bleibt Klartext
Kein früherer Eintrag darf ein Anfang des neuen Worts sein CRUNCH nimmt den ersten Treffer; Nr. 0–55 enthalten nichts, womit "DRAW" beginnt
Das Wort wird überall erkannt Aus DRAWN=1 wird DRAW + N=1 (im Emulator geprüft). Vorhandene Programme mit solchen Namen ändern sich beim Neueintippen
Code nur im BASIC-Teil ab BAS_COLD Der Monitor (0000h–1221h) benutzt feste Adressen, unter anderem für seinen Arbeitsspeicher bei 103Fh–1221h
Code muss vor 6900h enden Dort liegen zur Laufzeit die RS-232C-Puffer, ab 6B00h der BASIC-Arbeitsbereich

Platz. Hinter dem Code sind bis 6900h nur 84 Bytes frei; dieser Füllbereich (DEFS 6900h-$) schrumpft mit, wenn Code dazukommt. Reicht der Code darüber hinaus, bricht der Build mit "Code reicht über 6900h" ab. Mehr Platz gibt OLD_COPY bei 6561h: 159 Bytes, eine unbenutzte Kopie von 560Bh–56A9h, die man löschen kann. DRAW braucht mit den 3 zusätzlichen Tabellenbytes 94 Bytes, also muss OLD_COPY weg.

Bytegleichheit. Mit dem neuen Befehl ist das Abbild nicht mehr gleich dem Original. make check schlägt deshalb erwartungsgemäß fehl (Schritt 4).

Schritt 1 und 2: Schlüsselwort und Sprungtabelle

Zwei Zeilen machen DRAW zu Token 80h, B8h (Nr. 56) und verbinden es mit ST_DRAW.

1. Schlüsselwort (KWTAB_STMT). Das letzte Zeichen trägt Bit 7; die Tabelle wird 3 Bytes länger, alles dahinter rückt nach:

-        DEFB    0FFh                    ; Nr.  56: (frei)
+        DEFB    "DRA","W"+80h           ; Nr.  56: DRAW

2. Sprungtabelle (STMT_TAB, Eintrag 56):

-        DEFW    ERR_01                  ; Token 80h,B8h: (frei) -> Syntax Error
+        DEFW    ST_DRAW                 ; Token 80h,B8h: DRAW

Schritt 3: Die Routine ST_DRAW

ST_DRAW liest vier Ausdrücke durch Kommas getrennt, prüft jeden sofort und legt sie in einen Parameterblock. Erst wenn das Anweisungsende geprüft ist, ruft sie die Zeichenroutine auf. So wird bei einem Fehler nie halb gezeichnet.

Die Routine kann an beliebiger Stelle im BASIC-Teil stehen, zum Beispiel bei den Grafikbefehlen vor ST_CONSOLE. Dazu OLD_COPY löschen (von seinem Kommentarkopf bis vor den Abschnitt "RS-232C-ERWEITERUNG"):

; ------------------------------------------------------------------------------
;  ST_DRAW – Anweisung DRAW x1,y1,x2,y2   (Token 80h,B8h)
;  Linie von (x1,y1) nach (x2,y2), x 0-319, y 0-199, sonst Fehler 3.
;  Übergabe an GR_DRAWLINE: HL zeigt auf DRAW_PAR (x1, y1, x2, y2 je 16 Bit).
; ------------------------------------------------------------------------------
ST_DRAW:
        CALL    EVAL_INT                ; x1 -> DE, HL hinter den Ausdruck
        CALL    DRAW_CHKX
        LD      (DRAW_X1),DE
        CALL    SYNCHK
        DEFB    2Ch                     ; Inline-Parameter ','
        CALL    EVAL_INT                ; y1
        CALL    DRAW_CHKY
        LD      (DRAW_Y1),DE
        CALL    SYNCHK
        DEFB    2Ch                     ; Inline-Parameter ','
        CALL    EVAL_INT                ; x2
        CALL    DRAW_CHKX
        LD      (DRAW_X2),DE
        CALL    SYNCHK
        DEFB    2Ch                     ; Inline-Parameter ','
        CALL    EVAL_INT                ; y2
        CALL    DRAW_CHKY
        LD      (DRAW_Y2),DE
        CALL    CHK_EOS                 ; Anweisungsende, TXTPTR setzen
        LD      HL,DRAW_PAR
        CALL    GR_DRAWLINE             ; darf alle Register ändern
        JP      NEXTSTMT                ; weiter ab TXTPTR
DRAW_CHKX:
        PUSH    HL
        LD      HL,319                  ; größtes x
        JR      DRAW_CHK
DRAW_CHKY:
        PUSH    HL
        LD      HL,199                  ; größtes y
DRAW_CHK:
        OR      A
        SBC     HL,DE                   ; Grenze - Wert, C bei Wert > Grenze
        POP     HL                      ; Textzeiger zurück (Flags bleiben)
        JP      C,ERR_03
        RET
DRAW_PAR:
DRAW_X1:
        DEFW    0
DRAW_Y1:
        DEFW    0
DRAW_X2:
        DEFW    0
DRAW_Y2:
        DEFW    0
GR_DRAWLINE:                            ; eine Strecke über LINE_SET zeichnen
        LD      D,H                     ; DE = Punktliste (x1,y1,x2,y2)
        LD      E,L
        LD      A,01h                   ; eine Strecke
        JP      LINE_SET

Die Punkte, auf die es ankommt:

  1. Textzeiger in HL. Jede Hilfsroutine erwartet ihn in HL und gibt ihn dahinter zurück. Was HL sonst braucht, muss es retten: DRAW_CHK macht PUSH HL/POP HL um die Rechnung.
  2. Werte sofort ablegen. EVAL_INT wertet über EVAL aus und ändert dabei außer HL praktisch alle Register, auch die Schattenregister (EXX). Ein Wert in einem Register überlebt den nächsten Aufruf nicht. Darum wandert jeder Wert gleich nach DRAW_X1 usw.; der Stack ginge auch (PUSH DE), dann müssen die POPs in umgekehrter Reihenfolge stehen.
  3. Bereich mit EVAL_INT + eigener Grenze. EVAL_INT liefert schon 0–65535 und meldet negative Werte, Werte über 65535 (Fehler 3) und Strings (Fehler 4) selbst. Die Obergrenze prüft DRAW_CHK wie FN_POINT (319 bzw. 199).
  4. Trennzeichen mit SYNCHK. Das Byte dahinter ist ein Inline-Parameter, kein Befehl. Fehlt das Komma, kommt Fehler 1.
  5. Ende mit CHK_EOS und JP NEXTSTMT. CHK_EOS verlangt : oder Zeilenende und speichert die Stelle in TXTPTR. Deshalb darf GR_DRAWLINE HL und alle anderen Register frei benutzen.
  6. Nur Labels, keine Adressen als Zahl. Jede Adresse im Abbild als Label oder Label-Ausdruck schreiben (LD HL,DRAW_PAR, nicht LD HL,5A6Fh); sonst wandert sie nicht mit. make reloc-check findet solche Stellen.

Schnittstelle zur Zeichenroutine. GR_DRAWLINE bekommt HL = Adresse von DRAW_PAR. Dort stehen x1, y1, x2, y2 als 16-Bit-Werte (Low-Byte zuerst), bereits geprüft. Das ist genau das Format, das die Linienroutine von LINE erwartet: LINE_SET (zeichnen) bzw. LINE_RESET (löschen) nehmen in DE eine Punktliste (je Punkt x, y als 16-Bit-Werte) und in A die Anzahl der Strecken. Sie zeichnen nach Bresenham, übergehen Punkte außerhalb von 320×200, setzen die Grafikposition (GR_X/GR_Y) auf den letzten Punkt und ändern alle Register. GR_DRAWLINE setzt deshalb nur DE = HL und A = 1 und springt hinein.

Das Ergebnis im Emulator (DRAW wie oben eingebaut, ST_DRAW bei 5A3Ch, KWTAB_OPS von 1839h nach 183Ch gerückt; ST_DRAW angesprungen wie von DISPATCH). Die Parameterprüfung lief mit einem Stub für GR_DRAWLINE:

Eingabe Ergebnis
10 DRAW 0,0,319,199 Token 80 B8, LIST gibt die Zeile unverändert aus
30 D R A W 1,2,3,4:PRINT wird ebenfalls DRAW
DRAW 10,20,300,199 aufgerufen mit 10, 20, 300, 199
DRAW 2*5 , 20, 319 ,0 aufgerufen mit 10, 20, 319, 0
DRAW 1,2,3,4:PRINT aufgerufen, TXTPTR steht auf :
DRAW 320,0,0,0 / DRAW 0,200,0,0 / DRAW -1,0,0,0 Fehler 3, nicht aufgerufen
DRAW 1,2,3 / DRAW 1,2,3,4,5 Fehler 1, nicht aufgerufen
DRAW "A",0,0,0 Fehler 4, nicht aufgerufen

Mit der echten GR_DRAWLINE gesetzte Pixel im Grafik-VRAM (E000h + y*40 + x/8, Bit x mod 8):

Eingabe gesetzte Pixel (x,y) Grafikposition danach
DRAW 0,0,7,0 (0,0) bis (7,0) (7,0)
DRAW 0,0,0,5 (0,0) bis (0,5) (0,5)
DRAW 3,3,0,0 (0,0), (1,1), (2,2), (3,3) (0,0)
DRAW 319,199,317,197 (317,197), (318,198), (319,199) (317,197)

Hilfsroutinen für die Parameterabfrage

Alle Routinen erwarten den Textzeiger in HL, überlesen Leerzeichen selbst und lassen HL hinter dem Gelesenen stehen.

Routine Aufruf Ergebnis Fehler
EVAL_INT CALL EVAL_INT DE = Ausdruck als ganze Zahl 0–65535 (Nachkommastellen abgeschnitten) 3 (Bereich), 4 (String), 1 (Syntax)
EVAL_BYTE CALL EVAL_BYTE DE = 0–255, D = 0 wie EVAL_INT, > 255: 3
EVAL_ADDR CALL EVAL_ADDR DE = Adresse: $ + bis zu 4 Hexziffern oder ein Ausdruck 3
EVAL CALL EVAL D = 0: Zahl als Gleitkommawert bei (VALSP); D ≠ 0: String; A = nächstes Zeichen 1
GETSTR nach EVAL DE = Text, C = Länge des Strings 4 bei einer Zahl
SYNCHK CALL SYNCHK + DEFB zeichen Zeichen muss folgen, HL dahinter 1
CHK_CHR_ALT CALL CHK_CHR_ALT + DEFB zeichen + DEFW ziel Zeichen da: dahinter weiter; sonst Sprung nach ziel –
SKIPCOMMA CALL SKIPCOMMA ein Komma wird überlesen, falls vorhanden –
CHK_RPAR CALL CHK_RPAR ) muss folgen 1
CHRGET CALL CHRGET A = nächstes Zeichen; Z, wenn : oder Zeilenende –
CHK_EOS CALL CHK_EOS Anweisungsende muss folgen; TXTPTR wird gesetzt 1
CHK_NODIRECT / CHK_DIRECT am Anfang der Routine nur im Programm bzw. nur im Direktmodus 19
GETNAME_SN + GETVAR für Rückgabe-Variablen Variable suchen bzw. anlegen; Zuweisung über SAVEPAR1, SAVEPAR0, ASSIGN (siehe ST_INPAT) 1, 4
ERR_01, ERR_03, … JP ERR_nn Fehlermeldung, Abbruch der Anweisung –

Zwei Muster aus vorhandenen Befehlen helfen beim Erweitern:

  • Optionaler Parameter: CALL CHRGET / JR Z,ohne prüft, ob noch etwas folgt (so liest ST_AUTO seine Vorgaben).
  • Optionales Schlüsselwort oder Zeichen: CALL CHK_CHR_ALT mit dem Token- oder Zeichenbyte und einem Ausweichziel (so erkennt ST_ON die Form ON SRQ an den Tokenbytes 80h, D6h).

Schritt 4: Werkzeuge nachziehen und prüfen

Nach dem Einbau muss der Tokenizer die neue Tabelle kennen; die Befehlsreferenz folgt von selbst.

Werkzeuge anpassen:

  1. tools/sb6511tok.py: in STMT Eintrag 56 von None auf "DRAW" setzen.
  2. make ref trägt DRAW mit Token, Routine und der ersten Kommentarzeile in docs/BEFEHLE.md ein.

Prüfen:

  1. make: baut das neue Abbild; bricht ab, wenn der Code über 6900h reicht.
  2. make reloc-check: findet Adressen, die als Zahl statt als Label im neuen Code stehen, und lässt die Tokenizer-Tests auf verschobenen Abbildern laufen.
  3. python3 tools/test_sb6511tok.py --image build/SB6511_RS232.bin --sym build/SB6511_RS232.sym: Tokenizer-Tests gegen das neue Abbild; der Tabellentest bestätigt, dass sb6511tok.py und KWTAB_STMT übereinstimmen.
  4. Im Emulator: CLEARALL aufrufen, eine tokenisierte Zeile nach TOKTEXT legen, mit HL hinter dem Token nach ST_DRAW springen und bei NEXTSTMT anhalten. Für die Parameterprüfung GR_DRAWLINE durch einen Stub ersetzen, der HL merkt; für die Pixel danach den Speicher ab E000h auswerten (im Emulator ist das Grafik-VRAM gewöhnlicher Speicher). Die Ergebnisse oben stammen aus genau diesem Aufbau.
  5. Am Gerät oder in MAME (mz80b): MZF aus dem alten Header und build/SB6511_RS232.bin zusammensetzen (head -c 128 + Binärdatei) und auf dem Bildschirm prüfen (vorher mit GRAPH die Schreibebene wählen und die Grafik einblenden).

make check schlägt nach dem Einbau fehl, weil das Abbild nicht mehr dem Original entspricht. Für eine erweiterte Fassung sind ein eigener Zweig und eine eigene Prüfsumme sinnvoll; das bytegleiche Disassembly bleibt so als Referenz erhalten.
