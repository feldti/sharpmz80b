GP-IB und RS-232C

SB-6511 enthält Befehle für zwei Schnittstellenkarten: die GP-IB-Karte (IEEE-488, für Messgeräte) und – in dieser Variante – eine RS-232C-Karte mit Z80-SIO. Beide werden beim Start und nach jedem Fehler von IO_INIT (5EEFh) initialisiert.

GP-IB (IEEE-488)

Hardware

Die GP-IB-Karte wird über eine PIO und zwei weitere Register angesprochen. Die Bedeutung der Bits ist aus dem Code erschlossen; einige Statusbits sind noch unklar.

Port Name Bedeutung
C0h GP_C0 PIO Port A: Statuseingänge (Handshake, Bit 2 SRQ, Bit 4 EOI)
C1h GP_C1 PIO Port B: Steuerleitungen (Bit 0 REN, 1 IFC, 2 SRQ, 3 ATN); Bit 7 = Schnittstelle nicht bereit
C2h, C3h PIO-Steuerregister
C4h GP_C4 Datenbyte senden/empfangen
C5h GP_C5 Betriebsart der Schnittstelle (Kopie in GP_C5COPY)

Betriebsarten und Adressen

GPIB [M|S] [, hörer [, sprecher]] legt fest, ob der Rechner Controller (M) oder Gerät (S) ist, und setzt die eigenen Adressen (0–30; ohne Angabe ist die Sprecheradresse gleich der Höreradresse). Gespeichert wird das in GP_MODE (Bit 7 Systemcontroller, Bit 6 Controller aktiv), GP_MYLSN (20h+n) und GP_MYTLK (40h+n).

Gerätelisten werden mit ; getrennt (GET_ADDRS, bis 14 Adressen). Höreradressen 0–30 werden zu 20h+n, Sprecheradressen 0–31 zu 40h+n; andere Werte ergeben Fehler 37.

Befehle als Controller

Befehlsbytes werden mit gesetzter ATN-Leitung gesendet (ATN_ON … ATN_OFF).

Befehl Busbefehle Bedeutung
TRG adr[;adr…] UNL, Hörer, GET (08h) Geräte auslösen
DCL [adr…] mit Adressen: UNL, Hörer, SDC (04h); sonst DCL (14h) Geräte zurücksetzen
LCL [adr…] mit Adressen: GTL (01h); sonst REN abschalten Geräte in den Lokalbetrieb
LLO LLO (11h) Lokalbedienung sperren
PCT adr UNL, Sprecher, TCT (09h) Controllerrolle abgeben
REN Port C1 Bit 0 Remote Enable setzen
ICL Port C1 Bit 1 kurz Interface Clear (nur Systemcontroller)
WRT [/adr[;adr…],] ausdr[;…] (UNT, UNL, eigener Sprecher, Hörer), Daten Daten senden
RED [/adr,] var[,var…] (UNL, eigener Hörer, Sprecher), Daten Daten empfangen
CMD R|W, ausdr Text als Befehlsbytes mit ATN beliebige Busbefehle senden
SPOL adr, var UNL, SPE (18h), Sprecher, Statusbyte, SPD (19h), UNT Serial Poll
PPC adr, n Hörer, PPC (05h), PPE (68h+n), n = 0–7 Parallel Poll konfigurieren
PPOL var Parallel Poll ausführen
PPU PPU (15h) Parallel Poll aufheben
ON SRQ GOTO z bei Service Request zur Zeile z

WRT sammelt die Texte im Puffer bei 7074h (höchstens 500 Bytes, sonst Fehler 3) und sendet sie mit den Endezeichen EOI_WCHR1/2 (Vorgabe 0Dh, 0Ah). Ein ; am Ende unterdrückt sie. Ohne /adr muss die Karte bereits als Sprecher adressiert sein (Fehler 39).

RED liest eine Zeile bis EOI oder bis zu den Endezeichen EOI_RCHR1/2 (Vorgabe 0Ah) nach INBUF (GP_READLINE) und verteilt die durch , getrennten Werte wie INPUT auf die Variablen. Zahlen werden mit NUMSTR_EVAL geprüft (sonst Fehler 4).

ON SRQ GOTO z setzt SRQ_ON und SRQ_LINE. Vor jeder neuen Programmzeile prüft NL_SRQ die SRQ-Leitung (Port C0h Bit 2); ist sie aktiv, geht es einmalig bei Zeile z weiter.

CHK_SYSCTRL, CHK_NOTCTRL und CHK_IFREADY prüfen die Betriebsart (falsch: Fehler 34) und die Bereitschaft der Karte (Fehler 35).

RS-232C-Erweiterung

Die RS-232C-Befehle sind eine spätere Anpassung. Sie stehen bei 6600h–68ABh in einem Bereich, der vorher eine Kopie von 560Bh–56A9h enthielt (die alte Kopie OLD_COPY steht noch bei 6561h), und sind mit nur zwei Eingriffen eingebunden:

  • die Einträge 96–98 in STMT_TAB und die Wörter RSO, RSI, RSMODE in KWTAB_STMT,
  • JP SIO_INIT am Ende von IO_INIT (5F03h): beim BASIC-Start und nach Fehlern wird die SIO neu initialisiert.

Hardware

Z80-SIO an den Ports B0h (Kanal A Daten), B1h (A Steuerung), B2h (B Daten), B3h (B Steuerung). Die Baudrate wird nicht per Software eingestellt; sie kommt vom Takt der Karte.

Grundeinstellung (SIO_INITTAB, 13 Bytes per OTIR):

Register Wert Bedeutung
WR0 18h, 10h, 10h Kanal-Reset, Ext/Status-Interrupts zurücksetzen
WR2 (Vektor) Interruptvektor, von SIO_INIT eingetragen
WR4 4Fh Takt ×16, 2 Stoppbits, gerade Parität (änderbar mit RSMODE M)
WR1 14h Rx-Interrupt bei jedem Zeichen, „Status affects vector“
WR3 C0h Rx 8 Bit, Empfänger aus (RSMODE R/RX)
WR5 EAh DTR, Tx 8 Bit, Sender ein, RTS (RSMODE T)

Befehle

RSMODE {A|B} [,R n] [,T n] [,M n] [,RX n]
RSO {A|B}, ausdruck
RSI {A|B}, var[,var…]
Befehl Wirkung
RSMODE Kanal wählen; R n/T n Empfangs-/Sende-Datenbits 5–8; M n Byte für WR4 direkt (Taktteiler, Stoppbits, Parität); RX n: n ≠ 0 Empfänger ein, Ringpuffer leeren, Interrupts ein, n = 0 Empfänger aus. RX beendet die Anweisung
RSO Ausdruck in einen String wandeln und zeichenweise senden, abgeschlossen mit CR (0Dh). Kein Hardware-Handshake; Sende-Timeout: Fehler 32
RSI warten (mit BREAK abbrechbar), bis im Ringpuffer eine Zeile mit CR steht, sie nach INBUF kopieren und über den Zuweisungscode von RED auf die Variablen verteilen

Empfang per Interrupt

Der Empfang läuft im Interruptmodus 2: das I-Register ist 66h, die Vektortabelle SIO_VECTORS liegt bei 6600h. Jeder Kanal hat einen 256-Byte-Ringpuffer genau auf einer Speicherseite (A: 6900h–69FFh, B: 6A00h–6AFFh). Die Zeiger (RXA_WR/RXA_RD, RXB_WR/RXB_RD) werden nur im Low-Byte erhöht und laufen dadurch von selbst um.

  • SIO_RXA_INT/SIO_RXB_INT: Zeichen lesen, auf die Datenbits maskieren, in den Puffer schreiben. Holt der Schreibzeiger den Lesezeiger ein, wird die SIO zurückgesetzt und direkt aus der Interruptroutine Fehler 33 ausgelöst (der Fehlerbehandler setzt den Stack zurück).
  • SIO_SPA_INT/SIO_SPB_INT (Sonderempfangsbedingung): RR1 lesen und als Fehler 29 (Framing), 30 (Überlauf) oder 31 (Parität) melden.
  • RXA_GET: Zeichen aus dem Puffer holen (CY = 1 und A = Zeichen, CY = 0 bei leerem Puffer).

SIO_INIT hinterlässt DI; Interrupts werden erst durch RSMODE …,RX n wieder freigegeben.

Nicht benutzt: RS_TERM

Die Routine RS_TERM wird nirgends aufgerufen. Sie soll die Tastatureingabe umleiten (Zeichen von der RS-232C oder der Tastatur, Tastendrücke über Kanal A hinaus – ein einfaches Terminal) und patcht dazu die Adresse 06E0h. In diesem Monitor steht dort aber der Befehl CALL KEYSCAN; die Routine passt offenbar zu einer anderen Monitorversion und würde hier den Code zerstören.

Nr. Bedeutung
